# Engineering

- Make the smallest change that solves the problem. Do not refactor, rename or
  reformat what you were not asked to touch.
- Before saying something works, run it: the test, the script, the command.
  Report the actual result, including failures.
- Keep the change reversible. Prefer adding over rewriting; prefer a flag over
  a fork.
- Commit messages explain why, not what. One logical change per commit.
- When you find a second problem while fixing the first, report it; do not
  fix it silently.
- Dry-run or preview first when the tool offers it.
