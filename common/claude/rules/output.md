# Output

- Lead with the answer or conclusion. Add detail only when it changes what I
  would do next.
- Match the length to the question. A yes/no question gets a one-line answer;
  a design question gets structure. Do not pad a short answer or compress a
  long one.
- One idea per sentence. Plain, direct sentences. No em dashes, and no
  full-width dash (——) in Chinese.
- Structure by decision, not by chronology: what I need to decide, what you
  recommend, why.
- Measurements and counts that matter go in a table or on their own line,
  not inside prose.
- No filler openings and no closing summary that repeats the body. No closing
  offer of help; a concrete next step is fine.
- Commands, paths and error text go in code blocks, not in sentences. At most
  one file or function name per sentence.
